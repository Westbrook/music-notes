# Selection editing — plan and implementation

Approved on 28 August 2026. The design below records the reviewed plan; the implementation checkpoint at the end records the subsequent work. It builds on the existing Author workspace and notation-expansion work. The notation workbook remains separate. Code and automated checks do not constitute native browser or publication qualification.

Put common corrections in a small contextual toolbar that appears when the musician deliberately selects existing music in Write · Select. Keep a fixed position at the score's lower edge as the dependable presentation; place the same controls near a notehead only when measured space permits. More opens one persistent Properties pane directly. Do not move the entire Edit form into a floating panel.

Selection must not focus editing controls, open a large form, change the insertion recipe, or alter music by itself. A deliberate pointer activation of musical ink may establish score keyboard focus without scrolling; passive selection updates never steal focus. An accepted insertion must not raise this toolbar or redirect an existing inspection pane. The useful distinction is between selecting music, acting on it, and writing the next event.

| Option | Benefit | Cost and decision |
| --- | --- | --- |
| Entire editor beside the note | Everything seems close to its target. | Too much moving chrome, poor fit around dense music, and difficult short-screen behavior. Reject. |
| Fixed selection toolbar only | Predictable, compact, and straightforward for keyboard and phone use. | More pointer travel on a large score. Use as the first implementation and permanent fallback. |
| Compact contextual toolbar with optional Properties | Common corrections stay close to music; complex tasks have a stable working area. | Requires trustworthy geometry, focus, and fallback rules. Recommended destination. |

The engraver, composer, performer, design lead, IA specialist, accessibility reviewer, and reviewer using a Golden Krishna minimalism lens informed this proposal. The minimalism review's central requirement is to remove an unnecessary Edit step, not simply relocate it. The persona review is an analytical lens, not participation or endorsement by the real author.

**What is causing the current friction.** The selected-event form repeats its target in `#event-form-context` and the draft status, including when clean. Opening tools parks entry; resuming entry hides the tools. At narrower widths, an open pane hides both entry and selection actions. Several engraving fields apply immediately even though the surrounding form describes grouped Apply. These ownership and visibility policies should change before adding a new overlay. See [inspector rendering](../src/authoring/inspector-forms.ts), [workspace policies](../src/authoring/main.ts), and [responsive styles](../src/authoring/author.css).

**Common controls, without a permanent palette.** On a roomy screen, a single pitched note exposes `Value · Flat · Natural · Sharp · More`. A road note exposes `Value · Higher · Same · Lower · More`. Value displays the current written value and dots and opens a compact chooser. Full duration and alteration vocabularies remain available; nine durations beside nine alterations should not become permanent chrome.

On a narrow screen, use five controls total: `Location · Value · Pitch/Direction · More · Resume/Enter`. Location includes navigation and Return when needed. More opens Properties directly, with access to other tools and the existing deliberate pitch-drag action. Do not add separate Select, Tools, Return, and Drag buttons on top of this row. Preserve their functions through these named routes. Consequently, correcting a sharp takes Select → Sharp on desktop, and Select → Pitch → Sharp on a phone. The extra phone activation is preferable to shrinking targets or the music.

The phone row has a maximum of five controls, not five mandatory placeholders. Its state variants are explicit:

| State | Row contents |
| --- | --- |
| Single pitched/road/rhythm event | Location, Value, applicable Pitch/Direction, More, Resume. Omit irrelevant choices. |
| Chord | Location, Value, Pitches, More, Resume. |
| Attached mark | Location, Edit mark, Remove mark, More, Resume. Removal uses the exact child and current compatibility guards. |
| Multiple events | Location/count, Shared properties, Relationships, More, Resume. |
| Select more | Location/count, Range, Selection actions, Done, Resume. Done keeps membership and returns to ordinary Select; Resume ends this mode and resumes writing. |
| No event / structural selection | Location, Tools, Resume/Enter. An instruction or tuplet adds its explicit Edit action; unavailable note controls disappear. |
| Deliberate pitch drag armed | Location, fixed feedback space, Drag pitch handle, Done. More → Prepare pitch drag parks the pane and establishes this row before any press on the handle. Done restores ordinary Select. The handle stays beside visible notation and never moves or disappears during capture. |

In Enter, retain the entry recipe controls. Reuse the existing `#tools-toggle` slot: label it Properties when an inspection pane is held and restore that exact target/draft/scroll in one activation; otherwise label it Tools. This replaces a control, not an extra item. Merely restoring the pane does not park entry or retarget it to the latest insertion.

| Selection | Common actions | More / Properties |
| --- | --- | --- |
| One untied pitched note | Written value/dots; absolute flat, natural, sharp | Complete spelling and all nine alterations, attached marks, accidental display, stem policy, explicit conversion/removal |
| One chord | Written value/dots; Edit chord pitches | Explicit pitch list, compatible attachments and appearance; never choose an arbitrary chord tone |
| One rhythm note | Written value/dots | Compatible attachments and appearance; no pitch or clef controls |
| One road note | Written value/dots; Higher, Same, Lower | Articulations, ornaments and interval harmony; a tied continuation remains Same |
| Ordinary rest or rhythmic slash | Applicable written value/dots | Compatible properties; rests accept fermata, not note ornaments |
| Full-measure rest | Follows meter | Fermata; deliberate conversion to a written rest; no misleading nominal quarter-note control |
| Open improvisation slash | Write the rhythm… | Fermata and nominal span; do not imply prescribed attacks or pitched ornaments |
| Attached marking | Mark identity; Edit or Remove | Exact child row and owning-event route; interval Above/Below is musical direction, while articulation/ornament placement remains automatic |
| Multiple events | Count and scope; Shared properties; Relationships | Exact membership, compatible batch actions and explicit range tools; no single-note action on an arbitrary primary |

Existing marks and Add attached mark should be prominent in Properties, not buried under an “advanced” disclosure. Keep rare engraving controls below them. Common modifiers can use independent toggles where add/remove is unambiguous; complex intervals and compound text still need a named staged task. All supported microtonal, rhythm-staff, road, tuplet and marking capabilities remain reachable.

Use button groups selectively. Exclusive values use radio semantics even when drawn as glyph buttons; independent markings use checkboxes or stable-label pressed buttons. A quarter-sharp note must not show Natural selected merely because quarter-sharp is outside the three visible shortcuts. Show its real value in the context and complete chooser. Radios in an immediate-edit toolbar need the APG toolbar behavior: arrows move focus without editing, and Space/Enter chooses a value. A toolbar also needs its roving tab stop, not just a role attribute. [WAI radio pattern](https://www.w3.org/WAI/ARIA/apg/patterns/radio/), [WAI toolbar pattern](https://www.w3.org/WAI/ARIA/apg/patterns/toolbar/).

Reuse musical glyphs with readable accessible names and visible explanations for unfamiliar symbols. Keep augmentation dots distinct from staccato. Keep 44 px action targets and an obvious focus indicator. No hover-only route. Retained dropdowns must use the project's customizable native-select helper, including ordinary-select fallback; replacing some short choices with radio groups does not relax that requirement. [MDN customizable selects](https://developer.mozilla.org/en-US/docs/Learn_web_development/Extensions/Forms/Customizable_select).

**Separate an event's properties from musical relationships.** Properties replaces the selected-event Edit tab as the direct editing destination. Do not add another inspector alongside an unchanged duplicate Edit form. Use a single persistent tool pane: More opens its Properties view directly. A visible Other tools action switches that same pane to the Relationships / Instructions / Measure tabs; Back to properties restores its held target and scroll. Direct task actions may open the relevant view immediately. With no event selected, Tools opens the remembered general-tool tab. Note correction does not require entering that tab sequence, and two persistent panes never compete for score space.

| Task family | What belongs there |
| --- | --- |
| Properties | The selected event's own value, pitch/direction, attached marks, display policy and stem policy. A duration change may affect later onsets, but it remains an event property. |
| Relationships | Ties, tuplets and beam groups. These communicate relationships even when their source representation uses per-event attributes. |
| Instructions | Chord symbols, dynamics, tempo, text and improvisation instructions, including their recipients. Preserve both explicit `at` positions and accepted sequential source anchors; opening the UI must not freeze an implicit anchor. A chord symbol is not a chord pitch list or an attached road interval. |
| Measure | Meter, key, clef, barlines, structural bar operations and deliberate rest filling. Instrument/staff setup remains under Document; physical layout remains under Pages. |

Do not expose slurs, hairpins, cross-staff beams, range transposition or chord-tone selection as existing functionality. General beam-group editing also needs a new atomic operation; moving the current per-event beam field into Relationships alone does not implement it. Preserve an explicitly named low-level route until a proper group operation is ready.

**Keep entry and inspection independent.** Opening, scrolling or switching a tool does not itself need to park entry. Explicit correction intent may park it, retaining the writing bookmark and recipe. Resume returns to that bookmark in one action without closing the pane on a roomy screen. On a short phone, it may park the pane visually to restore score space, while preserving the target, fields and scroll position. The existing Enter-mode Tools slot, now labelled Properties, restores that work in one activation.

The clean inspector follows deliberate inspection selections in Select; it holds the last explicitly inspected target while entering notes. No Pin setting is necessary. A dirty inspector always holds its original target. Editing note B through accepted-value quick actions, or continuing entry, must remain possible while an advanced draft for A is held. Do not obtain this by removing draft-target guards: applying A while B is selected remains blocked with Return to A / Discard unless a separately designed, explicitly named off-selection Apply is introduced.

When inspecting A while entering at B, a musical action on A requires Return to A first. That named action parks the writing bookmark, selects/reveals A and enables its guarded editing; opening or reading the pane does none of these. More on B while A has a draft shows “Unapplied properties for A; B selected”, with Return to A and Discard and edit B. It must not pretend A's fields belong to B. B's quick corrections and Resume remain available. Retain corresponding distinct recovery choices if the attached-mark draft has another owner.

Maintain one implementation of quick property commands and one responsive common-control surface. Remove duplicate copies of the old common-property form from the expanded pane. A complete pitch/chord text draft is a distinct staged task, not a second unlabelled set of accepted-value controls. Quick actions never read unrelated pending form fields. If an accepted edit conflicts with a held draft, expose the existing review/recovery state instead of overwriting it. Label staged actions by task, such as Apply chord pitches or Apply attached marks; immediate actions must not sit under a misleading grouped-Apply promise.

**One target caption; messages only when they add information.** Present the selected object, staff, bar and voice once for the active editing surface, and reference that caption from its controls. Hide the entire pristine `.draft-notice`, not just its text. Show Unapplied changes for a dirty draft, field-local validation for a bad value, and a named recovery action for a stale or removed target. Routine selection should not also be repeated in `.pointer-status` and workspace notices.

Do not merge different owners for the sake of fewer words. A scalar draft for bar 8 and an attachment draft for bar 12 still need distinct compact captions. A held inspection target and the next-entry destination are likewise different information. This proposal does not introduce a new store of arbitrary drafts for many notes.

**Multi-selection needs exact membership before new gestures.** Start with whole events in one staff and voice, including ranges across bars and wrapped systems. A chord counts as one event. Store membership, a primary event, a fixed range anchor and range focus separately. A disjoint selection must never become all events between its endpoints. Cross-staff sets, lasso selection, chord-tone selection and group pitch dragging are deferred.

| Interaction | Proposed behavior |
| --- | --- |
| Click/tap in Select | Replace selection with that event; reveal compact actions without opening the pane or focusing controls. Deliberate score activation may focus the score. A mark keeps its exact child identity. |
| Double-click in Select | First click selects immediately; the second opens Properties for that same event once, under draft guards. Attached marks open their exact row. This is the same destination as Enter, not a second competing activation handler. No musical edit. More remains a visible single-click route. |
| Shift-click / Shift-Left or Right | Replace membership with the inclusive range from the fixed anchor; extend or shrink it as the endpoint moves. Shift after a disjoint set does not add a second range. Crossing staff/voice boundaries leaves the prior selection intact with an explanation. |
| Command-click on macOS / Control-click elsewhere | Toggle the exact event, preserving holes. macOS Control-click retains secondary-click behavior. A modified mark click addresses its owner event and names that choice. |
| Selection modifier while entering | Park entry before gesture handling; select only. Never insert or repitch first and repair afterward. |
| Select more / Done | Visible modifier-free mode: taps toggle membership. Keyboard arrows move focus without changing membership; Space toggles. Done retains the set. Range… retains From/Through controls for long passages. |
| Unmodified Left/Right at the score | Outside Select more, collapse a set to the previous/next single event relative to its primary. Park entry when necessary without replacing its recipe or writing bookmark. |
| Enter at the score | In Select, open Properties for one event, the exact row for a marking, or Selection actions for a group; in Enter, insert the exact recipe under current validation. Native controls retain their own Enter behavior. Tab from score focus enters the compact toolbar without requiring Properties. |
| Escape | Cancel the active gesture or close the transient chooser first. When handled at the score with no transient action, clear selection through the same reducer and reconcile highlights, counts and range fields; in Enter, park entry first. Never discard a draft implicitly. |
| Pitch drag | Exactly one eligible untied pitched note, no selection modifier. A group cannot silently drag its primary member. Touch movement continues scrolling. |
| Printed instruction text | A single click may select its instruction while leaving native behavior intact. Drag/double-click retains text selection; Edit instruction or Enter opens its form. Musical-glyph double-click handling does not apply to chord-symbol/direction/tempo prose. |

Do not add a double-click editing shortcut in Enter. Pointerup already commits an entry attempt; two valid releases can therefore insert twice. Keep ordinary entry immediate rather than delaying every tap or silently undoing the first insertion to reinterpret a double-click. The no-edit double-click guarantee applies to Select.

Plain selection establishes the primary and range anchor. Additive toggling preserves that anchor while it remains selected; removing it deterministically chooses the earliest surviving member in musical order, or clears it when the set is empty. If the primary is removed, choose the nearest surviving event in that voice, breaking ties toward the earlier event. Inspection focus may move independently; none of these changes moves the insertion bookmark. Selection of another staff/voice without a modifier replaces the set; an out-of-scope modified attempt leaves it unchanged.

For multiple events, show one count and scope, such as “6 events · Flute · voice 1 · bars 12–14”, and replace single-note controls. Exclusive properties show a shared value or Mixed with no choice checked; radios do not have a mixed checked state. Independent markings can show none/some/all. For “some”, name the action Add to all 6 events; add only missing instances and preserve existing IDs. Removal is an explicit remove-from-selection operation.

Implement safe batch properties deliberately: written value/dots on compatible events, eligible stem/display policies, standard articulation presence, and absolute alterations only when every member is an eligible untied single pitched note. Preserve untouched fields and enclosing tuplet ratios. A batch must stage all changes, validate the full score and commit once, or change nothing. Looping today's single-event `execute` calls is not a batch transaction. Choosing an already shared value creates no Undo. Overflow is rejected; shortening may leave an explicit incomplete draft, without manufactured rests or extra attacks.

Ties require consecutive compatible events in one staff/voice, potentially across bars, with complete spelled pitch sets or valid rhythm/road semantics. Tuplets require contiguous admissible contents within one bar/voice and cannot split nested boundaries. Clearing ties currently expands to every connected chain touched: call it Clear connected ties and show that expanded scope before acting. Existing road interval editing across a complete tied sound remains an explicit narrow scope; articulations and ornaments remain local. Disjoint selection never silently gains intervening events to make a relationship eligible.

**Application selection must not consume ordinary text.** Before adding gestures, fix the current event-routing gaps: `notation-select` loses modifiers/click count; pitch-drag admission does not test complete range membership; Escape can leave old From/Through values visible; and some native controls or readable transcript content across the shadow boundary can reach score-entry handlers. These are source-audit findings. Native browser highlighting has not been reproduced in this investigation.

Use one Author-only ownership classifier based on the composed event path and current musical hit geometry, including the pointer-inert system's host route. Exempt Source, inputs, links, disclosure controls, transcript/diagnostic text, annotation prose and every valid editable region before handling musical gestures or keys. Suppress mouse text-selection initiation only for owned interactive notation and apply any `user-select` rule deliberately across that rendered-notation shadow boundary. Preserve native text copying, touch panning and zoom. Do not disable selection on the whole editor or clear the browser's ranges globally. CSS `user-select` controls text selection, not the application's event set. [MDN user-select](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/user-select).

**Note-relative placement is an enhancement with a safe failure mode.** Use the actual measured pitched head for a single note; a chord's head group still denotes one event. Rhythm notes, road notes, rests and slashes use their painted event region without invented pitch geometry. Exact child markings keep their own geometry. Measures, annotations, tuplets and event sets use their appropriate docked tools, not a HUD attached to an arbitrary member.

The current rhythmic/staff-center anchor is not a notehead anchor. Event boxes also omit some sibling beam/tie ink. Initially protect the complete transformed ink bounds of every visible system, with approximately 8 CSS px clearance. Float only when the entire toolbar fits a clear gutter within the score viewport and avoids other controls. This conservative solver will often dock; a more permissive solver requires complete obstacle geometry. Never pad bars, shrink notation, change wrapping or widen the score to manufacture HUD space. See [renderer geometry](../src/engraving/render.ts) and [existing viewport targeting](../src/authoring/viewport-anchor.ts).

Keep controls in Author-owned HTML, never in musical Source or generated SVG. Use one state/controller and one surface, not independent dock and HUD implementations. An Author-owned HTML anchor can represent measured screen geometry; CSS anchor positioning is a progressive enhancement. Its overflow fallbacks do not test musical collisions, so application checks and an explicit dock fallback are still necessary. [MDN anchor overflow](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Anchor_positioning/Try_options_hiding).

Re-evaluate after settled render, outer and inner-system scrolling, viewport changes and control-size changes. Missing/stale geometry forbids floating. Freeze optional repositioning during a press, keyboard operation or open picker only while placement remains safe. If new ink overlap, clipping or target loss makes it unsafe, cancel the pending activation, dismiss the chooser if needed, and dock after releasing capture; never move an active button beneath the pointer or redirect its action. Preserve logical focus on a valid related control without automatically scrolling the score. Scrolling away retains the named target and an explicit Return action.

The compact toolbar is selection-owned HTML; its transient choice menus use native `popover="auto"` and `popovertarget`, not overlay disclosures. Value/Pitch opens a labelled choice surface and explicitly transfers focus into it. Its arrows belong to its controls; Space/Enter cannot insert music into the score. Escape closes only the innermost surface and returns focus to a valid invoker or score. Light dismissal must not steal focus back from a newly clicked field. Preserve the native behavior and in-flow fallback; use neither a mixed-form `role="menu"`, a focus trap nor a dimmed score backdrop. [MDN Popover API](https://developer.mozilla.org/en-US/docs/Web/API/Popover_API/Using).

Suspend floating selection controls and unrelated actions during entry/pitch gestures, but never hide or relocate the captured drag handle. Hide editing controls in Read, Pages and print. Pending Source retains the editing guard. Passive display, selection and placement change neither musical source, history, page layout nor turn-review fingerprints.

**Keep entry, selection and feedback in one dock.** The follow-up dock refinement places the Select control row below both the notation viewport and any reserved Properties pane, spanning the whole workbench. This supersedes placing it inside the score column or above the narrow-screen pane: neither opening a sidebar nor opening a bottom pane may move More and its siblings. Enter notes uses the same dock and bottom-left mode slot. On short phones the context row remains 48 px with 44 px targets; the existing entry controls grow upward from it. The dock is outside the scrolling notation, not over its last staff. No additional fixed footer or duplicated entry strip is introduced.

| Feedback state | Space and behavior |
| --- | --- |
| Clean Select | The relocated row contains the applicable controls and one target identity. No separate status/footer row or duplicate selection narration. |
| Gesture | The same row keeps its height. Preserve Location and the exact captured handle rectangle; only noncaptured property slots may give way to concise proposed pitch/time feedback. A prepared drag row has its handle and feedback area in place before pointerdown. Nothing resizes the notation viewport during capture. |
| Rejected action | Keep the failure in that existing area after release. Review occupies an existing action slot and opens complete details/recovery in UI, without adding a row. A new selection or related action restores normal controls while keeping the failure available in Review; it does not leave unrelated controls blocked indefinitely. |
| Enter | Place the existing entry rows immediately above the context/feedback row in the same bottom dock. Target a maximum of approximately 145 px total local controls, not entry controls at both page edges. The bottom row carries the writing target and feedback; the Properties restore control reuses its existing entry-toolbar slot. |

This explicitly preserves the approximately 180 px short-phone score requirement for ordinary Select with the pane parked. That height cannot also be promised for two-row Enter beneath the current header at 390 × 360. Measure Enter separately: the active staff, candidate target, entry controls and recovery must remain usable at their existing engraving size, including with a software keyboard. A layout that cannot provide them requires another review; hiding notices or shrinking music is not a pass.

An optional small local preview can show a different, shorter fact such as proposed pitch, only when it clears complete notation ink. Do not repeat the same sentence locally and at the edge. Long names and full failures stay readable through the named Location/Review routes rather than forcing another row. Announce meaningful target changes politely, not every pointer pixel, and avoid multiple live regions announcing the same event. If a safe local label cannot fit, the stable edge feedback remains sufficient. None of this uses `alert()`, `prompt()` or `confirm()`.

**Implementation sequence and review gates.** Each stage needs a testable plan and a team review before advancing. If a review fails, turn the finding into a narrower regression/acceptance criterion before revising the implementation. Do not weaken a geometry or draft-safety requirement merely to make the next review pass.

| Stage | Deliverable | Gate before the next stage |
| --- | --- | --- |
| 1. Ownership and selection | Pure exact-membership reducer; document epoch and selection version; modifier-preserving events; native input ownership; single-target drag admission; independent inspection/insertion policies | Inspection navigation changes its focused target while preserving the insertion bookmark and musical history; modifier gestures never edit; stale range fields cannot revive selection; drafts and native text remain safe |
| 2. Useful fixed controls | Compact context-sensitive toolbar, direct Properties route, separate relationship/instruction tasks, deduplicated captions, entry/pane coexistence, score-edge feedback | Ordinary correction counts, keyboard focus, all notation vocabularies, constrained-screen budgets, and uninterrupted entry pass |
| 3. Honest group editing | Shift/toggle/Select-more interfaces, exact highlights/counts, existing relationship gates and new atomic shared-property commands | Exact sets including holes; all-target eligibility; no primary-only batch edits; one Undo or no change; scope expansion explicitly reviewed |
| 4. Optional local placement | Measured note/event anchor, conservative ink exclusion, stable focus/pickers and fixed fallback | Native browser, dense-score and short-screen visual qualification; output unchanged. If placement fails, ship the already useful fixed presentation |

Selection/history work needs a separate selection version from musical revision and a document epoch for replacement even when IDs are reused. Snapshot the full membership/anchor with the independent insertion cursor for Undo/Redo. Revalidate removed, reparented or hidden-part targets after Source/view changes. Keep the current single-source compatibility accessor while migrating callers, and retain exact child-mark targeting. Gestures, confirmations and delayed actions capture the complete selection fingerprint, not just its primary ID. The existing `select()` cursor contract cannot be changed casually while other callers still depend on it.

The final plan review closed the design, IA, performer, accessibility and minimalism reviewers' tracked blockers. The composer and engraver's clarifications were also incorporated: preserve sequential annotation anchors, distinguish inspection from insertion, retain automatic standard-mark placement, and let geometry safety override a frozen HUD position. That checkpoint approved prototyping; it did not approve an unobserved implementation.

No application or test changes were made during the initial investigation. The implementation below followed the user's approval. Browser access to the designated review site remains unapproved from the prior cycle; no alternate browser, port or access method is being used to bypass that restriction.

## Implementation checkpoint

The fixed selection footer is the active presentation. Common accepted-value edits no longer require an Edit tab: a pitched note exposes Value and absolute Flat/Natural/Sharp choices, a road note exposes relative direction, and a group exposes exact Shared properties. Phone Pitch opens directly actionable common accidentals alongside all nine alterations. More opens untabbed Properties for an event, or the applicable relationship/instruction/structural tools for other selections. Properties and the three general tabs share one persistent pane.

Advanced event details and attached marks retain separate guarded drafts. Clean duplicate notices are hidden; distinct owners keep distinct captions. Entry continues without retargeting either draft, and phone Properties restores the held pane. Undo/Redo restores a parked writing bookmark from the actual restored writing cursor before Resume is rendered. Open slashes have a staged **Nominal span…** route that edits reserved time without prescribing attacks. Ordinary Value controls continue to describe written rhythm.

Exact event membership, primary, anchor and keyboard focus are separate from musical history and the insertion cursor. Shift replaces an anchored range; platform-appropriate additive selection preserves holes; Select more offers the same membership without modifier keys. Shared edits validate every member and commit once or leave all music unchanged. Source replacement and stale gestures/choosers use document epochs and complete selection bindings. Browser text input, readable transcripts, instructions, and touch panning keep their native ownership.

The optional note-relative placement module is implemented but **`contextualHud` defaults to false**. Its measured placement, projected-voice ownership, scroll/visual-viewport invalidation and render-start cancellation have automated coverage. Those checks use controlled measurements; they do not qualify real ink clearance, native pickers or pointer capture. The fixed footer must remain the production default until the native gates above pass.

Implementation reviews required successively narrower reproductions before accepting fixes:

| Review finding | Locked behavior |
| --- | --- |
| Held inspection and writing history | Quick edits and Properties never replace the writing recipe; explicit inspection after entry opens the requested target; a held draft remains reachable after range selection. |
| Same-note retry | Re-selecting the same note after rejection restores controls without changing selection version or musical history; the complete failure remains in Review. An accepted correction, including a semantic no-op, clears it. |
| Phone accidental depth | Select → Pitch → Sharp uses three explicit actions. Tests activate the common button rather than assigning a select value and skipping the picker. |
| Open-slash span | A visible, guarded nominal-span form preserves kind, `rhythmic=false`, identities, marks and exact tuplet timing; overflow rejects the whole edit and one Undo restores an accepted change. |
| Structural inspection | Creation follows its explicitly returned target within the visible part while preserving the independent writing cursor. Removal fallback is used only when the previous target was removed. Exact requested staff identity takes precedence over the writer's staff. |
| Parked Undo/Redo | After Redo while inspecting elsewhere, Resume inserts after the restored event, never between the previous and restored events. Undo while parked restores a resumable earlier anchor. |
| Focus and cancellation | Held-draft/range destinations support programmatic focus without extra Tab stops. Escape must cancel pending owned-button actions quietly while native fields and native popover dismissal retain their behavior. |
| HUD lifecycle | Both scroll axes, visual viewport changes, pending Source and deferred rendering invalidate unsafe placement immediately. Implicit projected voices are resolved through stable staff, measure and event identity; explicit voice ownership remains checked. ## Dock and menu refinement

The user's next review requires a common location for Enter notes and Select, stationary More controls, and Written value beside its invoker. One final workbench grid child now owns both modes. Status messages precede the workbench rather than consuming space below its dock. On short screens a limited Properties pane shares the remaining height with the score; its complete content scrolls without shrinking notation or adding controls. Explicit Expand task can still prioritize a form. This structural contract does not establish an entire staff will fit beside a form and software keyboard; native measurements remain required.

More and its Tools counterpart toggle the applicable visible pane. Closing is a presentation operation, even when a draft belongs to a different selected event: it never retargets, discards or applies that draft. Reopening preserves its fields and saved scroll. Specific tasks, double-click and Enter retain their open-only behavior. Expanded state is exposed through `aria-expanded` without changing the trigger's dimensions.

Small native choosers use the actual invoker for each opening, including Properties' alternate Spelling trigger. Positioning begins only after native opening, prefers available space above the dock, flips or clamps within the visible viewport, and preserves menu scrolling. Closing removes its observers and temporary styles. An unavailable invoker dismisses only its own chooser; focus recovery must not override a newly chosen external field. Ordinary in-flow fallbacks receive no positioning behavior. This menu placement is enabled independently of the disabled note-relative toolbar.

The stricter review also requires field reveal through the actual short-screen pane scrollport, visible focus when restoring a scrolled general tool without resetting its saved position, and rejection of pointer drops on the relocated dock. Tests must exercise those boundaries rather than count source declarations as native layout evidence.
