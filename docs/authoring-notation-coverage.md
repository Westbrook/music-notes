# Author coverage of the notation language

## Review scope — 2026-08-28

This cycle reviews the implemented notation language against actual Author workflows. It follows the separate authoring workspace, four persistent tool tabs, native popovers and customizable selects, independent entry recipe, exact timing, and guarded in-UI decisions already agreed in the layout review. The engraving demonstrations remain separate.

The engraver, composer, design lead, IA specialist, Golden Krishna analytical lens, and authoring-test reviewer inspected the current source. The lens applies published design principles; it is not participation or endorsement by the author. The review found broad existing support, rather than entire missing notation families. Several editing and discoverability gaps still need repair.

| Capability | Current authoring path | Preservation and limits |
| --- | --- | --- |
| Ordinary and quarter-tone pitch | Next entry and advanced pitch/chord fields; immediate accidental editing for a selected single note | Nine absolute alterations from −2 to +2 in half-semitone steps; `qf`, `qs`, `tqf`, `tqs` spellings. No arbitrary tuning. Pitch spelling and accidental display remain distinct. |
| Pitched, rhythm, and three-roads staves | New composition templates and Document → Score setup | Staff kind is explicit. Rhythm notes and road events never acquire an invented absolute pitch. Changing notation cannot silently remove incompatible music. |
| Three-roads directions | Entry/advanced Higher, Same, Lower controls | Relative to the last main pitch in the voice, including across rests. Written rhythm remains exact. Harmony and ornament tones do not become the next reference. |
| Articulations | Edit → Attached marks | Six types; all event kinds support at least fermata. Rests and open slashes permit fermata only. A chord marking belongs to the whole event. Placement is automatic relative to the drawn stem. |
| Ornaments | Edit → Attached marks | Five types, on single pitched notes and road main notes. Placement is automatic; no chosen auxiliary notes or playback realization. |
| Relative harmony intervals | Attached marks on a road event | Figures 1–13 with optional flat/sharp, required above/below direction, and no lowered unison. Several figures each refer to the main pitch; they are not chord-symbol text. |
| Written time and structure | Entry/Edit, Rhythm, Measure | Durations, dots, voices, nested tuplets, ties, meter/grouping, pickups, explicit completion, barlines and structural operations retain existing model validation. |
| Improvisation and instructions | Separate open/rhythmic slash choices and Markings | Open slash rhythm is improvised; rhythmic slashes prescribe attacks. Chord symbols, dynamics, tempo, rehearsal and directions remain fixed-onset annotations with explicit recipients. |
| Publication and interchange | Pages, project download/open, musical HTML export | Preserve notation kinds, pitch spellings, child marking IDs, exact timing and part instructions. Native PDF/paper output needs separate qualification. |

Direct staff placement and pitch dragging remain for supported single pitched notes. Rhythm and road entry use explicit kind/direction/value controls and Insert or Enter; they must not expose an inert pitch-drag action or fabricate pitch geometry. This cycle does not add a percussion map, arbitrary staff engine, ornament realization, automatic harmony voicing, playback, bulk modifier recipes, or automatic notation conversion.

## Requirements locked before implementation

| Gate | Required behavior and verification |
| --- | --- |
| `COVERAGE-VOCABULARY` | Maintain exhaustive authoring mappings for staff kinds, event kinds, directions, alterations and marking families/types, with a documented route or explicit limitation. Tests compare native choices with the model vocabulary and registered notation elements, so an added grammar feature requires an authoring decision. Avoid fixed dropdown counts. |
| `ENTRY-ALTERATION` | A labelled native alteration choice in Next entry can set all nine supported offsets on a valid single pitch without requiring suffix memorization. Preserve letter, octave, display policy and unrelated recipe fields. Retain invalid typed text with a local explanation instead of guessing a pitch. No history is created by recipe changes. |
| `ENTRY-KEYBOARD` | Preserve the documented A–G natural-pitch policy and state it beside the entry settings. In Enter mode, Enter on the score inserts the exact current recipe, including microtones, rhythm notes and road directions. In Select, Enter remains the selected-event edit action. Native fields/buttons retain their keys. |
| `ROAD-CONTEXTUAL` | Put the existing direction choice beside the staff in the space used by the unavailable pitch-drag action. An alternating road phrase must not require reopening settings for every event. Quick Edit exposes road direction directly and hides irrelevant accidental controls for pitchless events. Direction edits preserve rhythm, markings, entry recipe and tie validation. |
| `EDIT-DIRECT-ROUTES` | Quick Edit offers a named route to chord pitches/advanced properties and Attached marks in the existing Edit panel. Keep fixed-onset chord symbols/directions in Markings. Do not add a fifth tab, permanent modifier palette, or automatically open tools on passive selection. |
| `AUTHOR-MARKING-IDENTITY` | Retain a document-bound workspace target for the exact clicked marking while keeping its owner in EditorSession/cursor, preserving the tested session contract. Different marks on one event get distinct ink targets and an explicit edit route to their row. Highlight/reveal uses marking geometry. Removal, replacement, changed part, or unrelated selection invalidates stale child targets. Selection creates no history. |
| `MARK-DISPLAYED-BINDING` | Capture the displayed document, owner, row identity/family and baseline before processing native edits. An unseen source change or another document reusing IDs must not turn an old connected input into permission to edit the new target. Revalidate and retain the old user's draft safely. |
| `MARK-REVIEW-VISIBLE` | Show accepted-versus-draft changes and bind Review to the conflict the user actually saw. A later change before Review must be displayed before it can be acknowledged. No stale Review may enable Apply. |
| `MARK-EXTERNAL-DELETION` | Adopt an external deletion of an untouched marking during review. Preserve a locally modified missing row for explicit recovery; never silently recreate it or discard the user's change. Handle external family changes with the same intent distinction. |
| `MARK-FOCUS` | Adding a row reveals and focuses its first field within the tool pane only. Removing a row chooses a nearby surviving field/action. Successful Apply must not leave focus on a disabled button. Keep 44 px targets and the existing score-space budgets. |
| `MARK-AUTOMATIC-PLACEMENT` | Aligned with the concurrent notation change: articulations and ornaments use automatic placement opposite the drawn stem, or above a stemless event. Do not restore ineffective manual controls. Preserve imported legacy source values through unrelated edits, and merge changes to these inert legacy values without forcing a musical conflict review. Interval above/below remains an explicit musical control whose changes still require review. Migrate native-edit regressions to type/value changes without weakening their binding, conflict or focus assertions. |
| `QUICK-REOPEN-FOCUS-VISIBLE` | Added at the first implementation review: a quick editor reopened after its body was scrolled must reveal the accepted initial field for ordinary notes, chords, rhythm and road events as well as microtones. Scroll only the editor body; do not move the score or steal focus during passive refresh. Unit geometry checks supplement, but do not replace, native short-screen verification. |
| `AUTHOR-TIED-INTERVALS` | Offer an explicit complete-tied-sound scope for interval edits. A single transaction applies the requested interval changes across the whole connected road chain, including barlines, while keeping each segment's own articulations/ornaments, ties, directions, IDs, timing and unrelated source. No implicit inheritance or temporary tie removal. One Undo restores the complete prior state. Current-chain identity and relevant interval changes guard long-lived drafts. |
| `CONTINUATION-MODEL-PARITY` | Analysis rejects a three-pitch same-letter/octave cluster before offering continuation or final-ending review. Preserve valid two-alteration and ordinary microtonal chords. Analysis is read-only and consumes no source IDs/history. |
| `NOTATION-RECOVERY` | Explain pitched ↔ rhythm conversion through prescribed rhythmic slashes where valid; do not generally recommend replacing music with rests. Incompatible attached marks require deliberate removal. Name the affected event/mark and provide a reachable attachment-edit route; failed conversion changes nothing. |
| `STAFF-INITIAL-KEY` | Added by the final route audit: Add new staff must honor its visible Initial key for a pitched staff. Validate before staging source, retain the existing fallback when a command omits key, preserve later score key changes, and never introduce clef/key on rhythm or road staves. One Undo removes the addition; invalid input keeps the typed draft and accepted music unchanged. |
| `AUTHOR-EXPANSION-JOURNEYS` | Add a separate Author harness that boots the real application. Create/edit/remove through public controls, use its Undo/Redo and actual export/file-open actions, and check draft guards and responsive reachability. Component rendering and manually constructed controller tests are not substitutes. |
| `AUTHOR-EXPANSION-PAGES` | Use actual Author Pages with mixed quarter-tone/rhythm/road music, tied intervals, articulations, ornaments and scoped legends. Cover Letter/A4 and parts, child identity, whole-system/vector containment and absence of editor chrome. Musical mark edits invalidate page-turn reviews; passive selection does not. |

## Evidence and acceptance

The baseline includes substantial model, command, component and isolated-controller coverage. The focused event-marking suites passed 134 tests during this audit, but read-only reproductions exposed stale displayed bindings, stale Review acknowledgement, and untouched external-deletion failures that those tests did not cover. New regressions must precede those controller fixes.

Existing feature browser suites render MusicSurface directly. They are useful engraving evidence, but do not establish the complete Author creation/edit/export workflow. Separate feature-task documents record some manual Author checkpoints; those are not a substitute for a repeatable application harness covering this combined cycle.

### Review iterations

1. The first pass connected the existing grammar to frequent authoring actions: all nine entry alterations, exact-recipe Enter, inline road direction, contextual chord/attachment routes, exact marking targets, and atomic tied harmonies. Command, controller, real-workspace and geometry regressions were added at their respective boundaries. The continuation planner now validates the actual proposed event through the existing model rather than repeating a partial chord rule.
2. The next review tightened short-editor reachability. Initial and restored controls, as well as local errors, now reveal inside the note-editor body. The existing location context stays pinned when it fits and becomes ordinary scrollable content when it would cover the control. Nine failing regression cases preceded this fix; no score/document scrolling or passive focus changes were added by the inner reveal helper.
3. A concurrent engraving change removed manual articulation/ornament placement. Author preserves that simpler contract, retains imported legacy values without rewriting source, and ignores only those inert values during draft conflict comparison. Tests still require review for changed types, families, interval directions or tie dependencies. The new comparison behavior was locked with failing tests before implementation.
4. The final route audit found that Add new staff ignored its visible Initial key. `STAFF-INITIAL-KEY` specified the control-to-command behavior, first-bar semantics, later reference-key transitions, pitchless exclusions and rollback checks before repair. The optional command field and GUI binding now honor that value; all 18 new checks pass, including 13 that failed before the fix.

The Golden Krishna role is an analytical design lens. Its code reviews accept the ordinary writing flows, automatic placement, direct routes and explicit musical decisions; that is not participation or endorsement by Golden Krishna himself. Engraver review accepts the separate child identity/owner cursor contract; composer review accepts the complete tied-interval operation. Their bounded code reviews do not certify native layout or printing.

### Combined browser coverage prepared

The new `/tests/authoring-notation-browser.html` boots actual Author workspaces in isolated recovery slots. Its 11 groups cover native entry/quick alteration choices, rhythm and road writing, all attachment families, interval validation, exact child editing, tied harmonies, long-lived draft safety, actual project and musical-HTML export/reopen, and Letter/A4 Pages for the score and three parts. Three additional buttons prepare GUI-authored visual fixtures. Result JSON is published in `#author-notation-browser-results`; visual setup results use `#author-notation-visual-results`.

Export tests observe the iframe's real Blob/download boundary and feed the captured bytes through its file-open action. Print is intercepted only at the request boundary. Source edits supplement conflict cases, not the core creation/export fixture. These are compiled test journeys, not claimed browser passes. In particular, short-screen control visibility, native pickers, real input, scoped legends in physical output, saved PDFs and printed pages still require execution and inspection.
