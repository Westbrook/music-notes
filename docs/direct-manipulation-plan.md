# Direct staff interaction

This extends the separate Author workspace. The notation workbook and its source grammar do not acquire editing behavior. The specialist team agreed on the first implementation below, then reviewed the implementation through the cycles recorded here. The first implementation and 27 August evidence are historical records. The [28 August status](#writing-surface-implementation-status--2026-08-28) describes the current routes and supersedes earlier statements about entry handles and unsupported rest placement; it does not reuse those earlier browser results as current native acceptance.

## First implementation — historical scope

1. **Select is the default.** A click selects music without changing it. In **Enter notes**, a click on a staff adds the configured single note at an existing musical boundary. A small current-note handle can also be dragged onto the staff without leaving Select mode.
2. **Drag a notehead vertically to change pitch.** The first release supports an untied single note. Its duration, onset, alteration, accidental display, stem policy, beam policy, source identity, and tuplet membership remain intact. Chords, tied chains, rests, and improvisation slashes remain editable with the existing controls. Horizontal movement does not move musical time.
3. **Show the proposed result before committing.** Use final renderer notehead/staff geometry and an engraved ghost, with a target caret and a concise label naming pitch, staff, voice, measure, exact whole-note onset, and rhythmic scope. Before, After, and Replace refer to the existing position control. Replacing an initial full-measure rest is explicit. Ordinary rests are never silently split or overwritten.
4. **Use the real musical model.** Invert the effective measure clef on the staff's diatonic half-space grid. Preserve the visible pitch field's alteration for new notes and the source note's alteration for pitch changes. Never infer a sharp from a key signature, convert x coordinates into invented beats, guess a different voice, or cross a tuplet boundary implicitly.
5. **Make each gesture one reversible edit.** Preview on detached source, validate the whole score, then commit once on release. A no-op makes no history. Escape, a cancelled pointer, another pointer, loss of capture/focus, an outside release, scrolling, resizing, or a changed source/projection cancels without changing accepted music.
6. **Keep touch scrolling and alternatives.** Normal score touches can tap or scroll. Deliberate handles allow touch dragging without disabling scrolling over the score. Native labeled forms, Insert/Apply buttons, and existing keyboard entry remain alternatives. Feedback is announced only when the snapped target changes.
7. **Protect reading and publishing.** Read and Pages accept no note gestures. Read cannot change music through Undo/Redo. Pointer targets, previews, and handles do not print. Existing physical page layout, publication checks, native popover menus, and customizable native selects remain unchanged.

Fix actionable issues and repeat the affected tests and reviews until the team accepts the implemented scope. Keep real-device and publication limitations separate from automated evidence.

The historical checks cover geometry across clefs and chord head displacement; click/drag insertion; vertical pitch editing; exact tuplets/voices; no-op/undo/recovery; invalid/outside/stale/cancelled gestures; touch-scroll protection in the application; Read/Pages protection; scaled/scrolled geometry; native controls; and notation-workbook regressions. ## Iterations

- Cycle 1: all five specialists agreed on the three gestures and the explicit initial scope. Implementation added per-head geometry, engraved previews, pure staff targeting, a pitch-only command, and a pointer lifecycle. The existing Read-mode Undo path was closed. The first real browser staff click placed F4 in one transaction; 10 geometry cases, including 108 engraved preview variants, passed.
- Cycle 1 review: the team found a no-op selection/inspector mismatch, an automatic Replace setting after Add measure, possible targeting through a wrapped-system gap, a new-note ledger limit incorrectly applied to existing notes, missing-preview transforms that could leave a valid candidate, and stale error feedback. The design review found that drag handles needed to stay reachable beside a long score.
- Cycle 2 implementation: completion now synchronizes the selected event and all its controls even for a no-op, and clears the old passage range. Add measure preserves the chosen insertion position. Frame/viewport clipping and native-control exclusions guard targets; existing ledger notes keep their original staff. An unavailable preview rejects the proposal, and a later successful gesture clears an obsolete operation error. The drag handles and stable feedback stay in a compact sticky Write strip beside the score; local preview labels are shorter and constrained to the visible workspace.
- Cycle 2 verification: all 19 pointer browser cases pass, including a CSS-scaled, translated, and internally scrolled score. The fixtures exercised 36 detached previews and 20 committed gestures. Separate browser mouse actions on the production Author page placed F4, dragged it to A4, undid the pitch change once, and dropped the entry tile to append G4 while retaining Select mode. These production checks used no pointer-capture shim.
- Cycle 3 visual review: at phone width the local preview label covered a preceding staff. Label placement now checks the transformed ink bounds of every visible system as well as the preview and viewport. If no clear position exists, the optional label is omitted and the sticky controls retain the complete target description. All 19 pointer cases pass again; the design lead inspected the final 1180×660 and 390×660 previews at bar 7 of a scrolled score and accepted both.

## Writing-surface implementation status — 2026-08-28

Deleting the final note or rest now leaves an ordinary voice empty and its measure explicitly incomplete. It does not create another rest. New blank pitched, rhythm and three-roads starters also begin with empty incomplete voices; the road starter retains its performance legend. Composed studies and Add measure retain their authored or explicit rests. Empty ordinary voices expose an onset-zero anchor for entry with the same exact voice and source-identity checks. Before and After can start that voice; Replace still needs an event. Pickups remain guarded, and an empty draft is not approved silence or an ordinary publishable ending.

**Write notes** now supports staff click and prepared-handle drop for ordinary written rests on pitched, rhythm and three-roads staves, as well as single pitched notes on pitched staves. A rest uses the chosen duration and dots at an existing musical boundary in the active voice; height has no pitch meaning, and dormant pitch text is not read or rewritten. No event is split, no missing silence is invented, and overflow, stale targets and invalid tuplet scope reject the whole gesture. Full-measure rests still use explicit Insert here/Enter. Chords, rhythm notes, road notes and slashes retain their exact-entry routes. Moving an existing rest through musical time is not implemented.

The current drag route is **Write notes → Options → Prepare note drag / Prepare rest drag**, then the visible handle. Done or Escape returns to ordinary writing. Earlier references above to dropping an entry tile while remaining in Select no longer describe an exposed user route; synthetic handler admission cannot make a hidden control available. Existing-note pitch correction remains a separate Select operation, limited to eligible untied single notes with fixed musical time.

Write notes and Select remain visible in fixed slots. Write notes resumes the independent saved point C even when B is selected; an active Write notes press only returns focus. Location's Start writing here deliberately chooses a different point. With score focus in writing, N/R choose note/rest tools and Left/Right moves the writing point without editing music or replacing selection; Escape does not otherwise leave writing. Options and Value are separate native popovers, and Insert here remains an exact-entry alternative. The complete selected Pitch chooser supports letter, octave and absolute alteration without reading unrelated retained drafts.

More uses spare width beside an independently chosen writing frame or a deliberate task sheet with Return to score. It does not shrink the notation or change system breaks. The header provides a compact global feedback summary and Review retains the full explanation; errors do not displace the palette controls. Recovery warnings persist through ordinary status and navigation, with Download project in Review; a request does not prove a saved file or repair local recovery. The normal palette has a 48px CSS target at default text size, with controls at least 44px square, not a measured native result. The optional note-relative toolbar remains off by default. A dedicated next-road-note Direction chooser is implemented and has completed bounded automated and composer review; it prepares Higher, Same or Lower for Insert here/Enter without implying road-note pointer entry.

These changes have focused automated coverage. Current aggregate reconciliation is still in progress, and no all-tests pass or final team acceptance is asserted here.
