Workspace task journeys

These scripted journeys use the actual Author application, complete musical tasks through visible controls, and inspect accepted musical source, exact timing, working state, real notation geometry, and physical page composition. Each fixture has its own recovery workspace.

Qualification limits: synthetic DOM clicks, key/pointer/wheel events, and form changes exercise application routing, not trusted native input. Pointer taps use unmodified native capture; there is no capture shim in this harness. Explicit stale-event cases deliberately deliver events to disabled or modal-inert controls to test application guards; they do not claim that native users can activate those controls. File cases use only in-memory files: the identity case sends no change event; the asynchronous case defers one fixture File’s own text() and delivers synthetic change events, then cancels the import decision. Neither case uses a picker or accepts an imported project. Confirmations use the app’s actual dialog and visible buttons. Passing these checks does not establish software-keyboard behavior, native picker dismissal, hardware capture, confirmation fallback behavior, a twenty-minute human walkthrough, or saved PDF/printed output.
